Current project guide

A guide to the current MultiWealth application: Overview, Personal Finance and Real Estate. Updated September 2026.

The application is in a private repository and under active development. This website is its showcase; it does not provide a hosted finance account. Ask about access before following the installation steps.

Find your way around

WorkspacePages
OverviewNet worth, assets, liabilities and breakdowns across your holdings.
Personal FinanceAccounts, Transactions, Classify, Planner, Credit, Investments, Tangibles, Pots and Catalog.
Accounts tabsAccounts, Statements and Bank Agents. Chequebooks live inside account details.
Real EstateEstate, Tenants, Mortgages, Rental Income, Expenses and Documents.
CatalogProducts, Compare, Offers and Alerts, plus Key Facts Statement history.

Prerequisites

Use a local PostgreSQL instance and a supported Node release. These requirements reflect the installed Vite 8 and Prisma 7 toolchain.

ToolRequirement
Node.js22.12+ on the Node 22 line, or Node 24+. The dependency engine ranges also accept Node 20.19+.
PostgreSQL14+; a running server and a role that can create your local databases.
Python3.11+ for the optional Intel catalog service.
GitAccess to the private application repository.

Installation

The example below creates a fresh development database. Use your own database role and password in the connection strings.

1. Clone and install

Terminal
git clone git@github.com:Halkhoori2000/MultiWealth.git
cd MultiWealth
npm ci
npm --prefix server ci

2. Configure the backend

Create server/.env from server/.env.example:

server/.env
DATABASE_URL="postgresql://user:password@localhost:5432/multiwealth_dev"
INTEL_DATABASE_URL="postgresql://user:password@localhost:5432/multiwealth_intel"
PORT=3001
HOST=127.0.0.1

3. Configure the frontend

Create a root .env.development.local file for this development setup. The frontend’s API URL must match the backend port.

.env.development.local
VITE_API_URL=http://localhost:3001

4. Create the app database and generate clients

Run from the project root, after setting your PostgreSQL credentials. createdb uses your local PostgreSQL connection settings.

Terminal
createdb multiwealth_dev
npm --prefix server run db:generate
cd server
npx prisma migrate deploy
cd ..

The main app schema uses Prisma migrations. The separate Intel schema uses Alembic; initialize it using the Intel setup below when using the Catalog.

First launch & deployment modes

For the fresh development setup above, start these commands from the project root in separate terminals:

Terminal 1 — backend
npm run server
Terminal 2 — frontend
npm run dev

Open http://localhost:5173. The backend health endpoint is http://localhost:3001/health.

Existing personal deployment

The repository also includes a separate pair of scripts for its configured multiwealth_prod database:

Terminal 1 — existing database
npm run server:prod
Terminal 2 — matching frontend
npm run client:prod

This pair uses backend port 3002 and frontend port 5174. The frontend loads .env.proddb. The server script expects a local PostgreSQL role matching your OS username. Use this pair only after configuring that database and applying its migrations; it does not create a database. Keep each frontend paired with its matching backend.

Accounts

Open Personal Finance → Accounts to create a current account, savings account, fixed deposit, credit card or loan. Set the institution, account kind, currency and balance. Link a catalog product where available to keep its published terms nearby.

  • Account detail brings together balances, transactions, statements and account-specific controls.
  • Liabilities include credit cards and loans; card utilization is shown using the account’s credit limit.
  • Transfers connect movements between tracked accounts so they can be distinguished from ordinary spending.

Import statements

Use the import action in Accounts for supported PDFs or CSVs. Review each file before confirming it.

  • Check the detected institution, destination account, currency and statement period. A supported statement can prefill a new account.
  • Inspect transaction rows, categories, payees and duplicate flags. Parser warnings and reconciliation differences need review.
  • For a supported locked PDF, provide its document password when prompted.
  • Confirm the import after reviewing the selected rows. Duplicate detection reduces repeat imports; the preview is the place to check the result.
  • Keep the original PDF attached to its statement record for later inspection.

See the current parser coverage. Bank-specific PDF parsing and generic CSV parsing have different coverage.

Statement coverage & reconciliation

Open the Statements tab beside Accounts. A month-by-month grid shows coverage across accounts, with statement records below it.

  • Inspect missing months and expected statement dates; mark months where no statement is expected.
  • Filter by account or month and open, attach or replace a source PDF.
  • Review opening and closing balances, flow totals and reconciliation badges.
  • Keep reissued statements traceable through their replacement records.

Transactions

Search, filter and review imported and manually entered transactions in Personal Finance → Transactions.

  • Filter by account, date, category, payee and other available fields.
  • Edit classifications, add notes and review transaction status.
  • Use tags and links to connect transactions to Pots or other records.
  • Export transaction rows to CSV for your own analysis.

Classify & recurring payments

Classify is the shared home for categories, payees and matching rules. It replaces the old separate Categories and Payees pages.

  • Map noisy bank descriptions to recognizable payees, and review suggested classifications.
  • Manage categories and assign spending, savings or investment buckets for the Planner.
  • Recurring detection groups repeated payments; recurring rules and series help track expected activity.

Chequebooks

Open an account’s detail panel and its Chequebook. Cheques are not a separate sidebar page.

  • Record cheque numbers, payees, amounts and due dates against the account.
  • The current statuses are written, cleared, bounced and cancelled.
  • A bounced cheque can return to written or be cancelled. Cleared and cancelled states are terminal.
  • Clearing supports linking the matching account transaction. Pending cheque totals help show upcoming commitments.

Credit & AECB reports

Open Personal Finance → Credit for imported AECB report history. The page currently receives reports through the configured agent ingestion workflow; it has no direct PDF upload button.

  • Report history: view scores and bands from stored reports, compare changes and open archived documents.
  • Facilities: match reported accounts to your tracked accounts and inspect limit or balance differences.
  • Current position: compare report snapshots with current card balances and utilization.
  • Estimates: the page includes a score estimator and paydown scenarios. These are model outputs, separate from the score printed in an AECB report.

Brokers & portfolio

Add a broker in Investments for each platform you use. Holdings and uninvested broker cash contribute to the portfolio view.

Track stocks, funds and crypto, with broker-level breakdowns, documents, allocation targets and portfolio history. Values are consolidated into AED while retaining the holding’s currency.

Holdings

Add a holding under its broker, select its type and symbol where applicable, and record quantity and cost. Review the price source, valuation and currency conversion shown by the application.

Broker cash is tracked separately from invested holdings, so cash awaiting investment remains part of the portfolio.

Investment activity

Record buys, sells, dividends and interest. Investment transaction history provides the context for quantities, cost basis and performance.

Supported investment statement parsers currently include Al Ramz and Binance. Other brokers can still be tracked manually; a broker record does not imply automatic statement support.

Live watchlist

Open Live Prices from Investments to use the standalone market board.

  • Follow symbols from ADX, DFM, US markets and crypto, subject to the external provider’s coverage.
  • Switch between Cards, Fit and List layouts, reorder symbols and group by exchange.
  • Filter the board, change chart ranges and inspect exchange status.
  • Charts and quotes require an internet connection. Availability and quote timing depend on the provider.

Real Estate

Real Estate is a dedicated workspace with six pages:

PageUse it for
EstateProperty values, ownership shares, status, purchase details and off-plan payment milestones.
TenantsTenant records, lease details and the relationship to each property.
MortgagesLinked borrowing, repayment schedules and property debt.
Rental IncomeRent schedules, due payments and recorded receipts.
ExpensesProperty costs and their supporting records.
DocumentsFiles attached to properties and their related records.

Co-owned properties retain ownership shares. Off-plan payment schedules connect commitments and milestones to the wider wealth view.

Tangibles

Personal Finance → Tangibles tracks physical assets, including vehicles and valuables, with purchase price, current value and ownership details.

Attach relevant documents such as vehicle registration and insurance, record asset identifiers, and track changes in value. The dedicated Real Estate workspace handles property operations such as leases and rent.

Pots & goals

Pots bring goals, upcoming commitments and tracked balances into one view.

  • Envelopes track money set aside and progress toward a target.
  • Trackers reflect linked balances, such as an account, investment portfolio or debt.
  • Views group values for a particular goal or perspective.
  • Targets, dates and linked contractual milestones can inform the monthly amount to set aside.
  • Contributions and transaction links keep progress connected to your records.

Monthly Planner

Use Planner to organize income, spending, savings and investment for a selected month.

  • Set the plan and compare it with recorded activity.
  • Category buckets come from Classify; Pots can contribute planned allocations.
  • Review recurring commitments and the difference between planned and actual amounts.
  • Use month navigation to inspect past activity and upcoming plans.

Product Catalog

The Intel registry contains 29 bank and issuer integrations, including AMEX Middle East. This is a count of configured integrations, not a guarantee that every product or field is available.

Browse accounts, cards, deposits and loans; filter by institution or product category; compare terms and link a catalog product to your account. Source links and Key Facts Statements provide context for the displayed terms.

Catalog data depends on the optional Intel service and its latest successful refresh. The project does not bundle a fixed, guaranteed product count.

Alerts & KFS history

Catalog → Alerts shows recorded product changes and before/after values. Key Facts Statement history allows inspection of document versions and differences.

Changes appear inside the application after a successful refresh. There is no built-in push notification service. Coverage and refresh health depend on the public source and scraper setup.

Offers & campaign history

Catalog → Offers tracks published campaigns, validity windows, source links and material edits. It distinguishes a routine check from an actual offer update.

Campaign producers currently cover ADCB, Citi, FAB, Mashreq, RAKBANK, Al Hilal and NBF. Discovery completeness varies by institution; campaign coverage is narrower than the overall catalog registry.

Optional Intel setup

Intel has its own database and Python environment. Its connection must refer to the same database as the backend’s INTEL_DATABASE_URL. Run from the project root:

Terminal
cd services/intel
python3 -m venv .venv
.venv/bin/pip install -e .
createdb multiwealth_intel
export INTEL_DATABASE_URL="postgresql://user:password@localhost:5432/multiwealth_intel"
.venv/bin/python -m intel migrate
.venv/bin/python -m intel seed
.venv/bin/python -m intel scrape citibank
.venv/bin/python -m intel health

The scrape command contacts public bank sources. A daily scheduling script is included, but cloning the project does not install that schedule. Follow services/intel/README.md in your checkout for scheduling and coverage diagnostics.

Bank Agents

The Bank Agents tab beside Accounts provides configured bank connections, credential entry and sign-in prompts for the local adapter workflow.

This integration is under active development. Support depends on the individual bank adapter, its current eligibility and your local browser setup. It is not a universal bank-sync service. Review staged imports before accepting them.

Copilot & agent integrations

The in-app Copilot has an Activity feed for ingestion and classification events. Its Chat view is still a UI preview with a disabled input; the showcase does not advertise it as a working chat assistant.

Agent-driven statement staging, classification and credit report ingestion require a separately configured workflow. An optional MCP adapter also exposes selected app and catalog operations to a configured agent environment.

External integrations use their own services and permissions. They are not automatically installed or enabled by starting the frontend and backend.

Statement parser coverage

The current bank-specific PDF parser registry covers these formats. Support refers to known statement layouts, not every document issued by an institution.

InstitutionRegistered PDF format
RAKBANKAccount and credit card statements
ADCBAccount, credit card and consolidated account statements
First Abu Dhabi Bank (FAB)Supported FAB statement layout
Mashreq NeoSupported Neo account statement layout
CitiCredit card statements
Al RamzInvestment statements
BinanceInvestment statements

Emirates NBD does not currently have a dedicated PDF parser in this registry. It can be represented in Accounts and the Catalog without implying PDF import support.

CSV is format-based

The generic CSV importer recognizes date and description columns plus debit/credit columns or a single amount column. Compatibility depends on the headers and values, rather than a bank-specific support badge. For example:

Illustrative CSV
Date,Description,Debit,Credit
2026-09-01,Example purchase,125.00,
2026-09-02,Example receipt,,500.00

Always inspect the parsed rows and any skipped-row warnings before confirming.

Storage & connections

The core app stores financial records in PostgreSQL and uploaded documents on your host. Backups, access to that machine and deployment are controlled by you.

Market data and embedded charts contact external providers. Intel fetches public banking information. Optional bank adapters and agent integrations have additional connections. Self-hosted storage does not mean every feature is offline.

All balances, scores, rates and transactions in the showcase previews are fictional examples.

Shortcuts & backups

  • Command search: press ⌘K or Ctrl+K to open the command palette.
  • Page search: several lists use / to focus their search field.
  • Keep source documents: statement coverage and reconciliation are easier to review alongside the original PDFs.
  • Back up the right database: the repository backup script defaults to multiwealth_prod. Set BACKUP_DB or BACKUP_DATABASE_URL for another deployment.
  • Include files: non-statement uploads are included by default; INCLUDE_UPLOADS=1 includes statement PDFs too. See scripts/backup-db.sh for retention and restore instructions.
Example: back up the fresh development setup
BACKUP_DB=multiwealth_dev INCLUDE_UPLOADS=1 npm run backup

Database credentials and the selected backup destination must match your own setup. Report a documentation issue.
